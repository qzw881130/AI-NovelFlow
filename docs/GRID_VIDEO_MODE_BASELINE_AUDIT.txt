## Legacy #13→#14/#14A 清理边界

- 新任务 H3 默认路由为 `phase_b`；视频页仍显式提供 `Legacy #13 → #14` 选项。早期模板类型 `h3_multi_keyframe_prompt`、`h3_execution_optimizer_prompt`、`h3_preflight_repair_prompt` 在提示词管理中各有 1 个活跃系统模板；当前 20 部小说中没有选择这三种模板的小说。正式 Phase B 类型有 1 个系统模板和 1 个实验自定义模板，其中实验小说绑定自定义模板。
- SQLite 只读统计：`shot_video` 历史任务中，持久化 `phase_b` 872 条、`legacy` 15 条、无路由字段 289 条。现有 `persisted_h3_prompt_pipeline` 会把无路由字段解释为 Legacy。因此删掉旧执行代码时，至少 304 条历史任务需要保持只读展示，重试不能静默改走 Phase B。
- Phase B 当前从 `h3_execution_optimizer` 引入 `workflow_duration_limits`；其所用 `h3_single_stage_experiment` 编译器还引入 `_identity_picture_subjects`、`subject_bindings`、`workflow_duration_limits`，并在内部引入 `check_authority`、`retime_temporal_manifest`。这些是迁出或重构后才能删除旧优化模块的直接依赖。`h3_single_stage_experiment.py` 虽带实验名称，却承载正式 Phase B 的编译入口，不能按文件名直接删除。
- 活跃入口分布：后端模板类型/注册与初始化、小说模板绑定、`shots.py` 请求路由、`shot_video_service.py` 执行分支及优化/修复服务；前端视频页 H3 路径选择、提示词管理、小说模板表单、日志标签和 API 类型。下阶段应先迁出 Phase B 共用函数并保护已记录的单镜结果，再移除 Legacy 新任务入口、模板与无用代码。

结论：基线已建立；Legacy 代码确有历史读取和 Phase B 工具依赖。现在没有删除操作，下一阶段可按此清单开始提示词基础与清理工作。
