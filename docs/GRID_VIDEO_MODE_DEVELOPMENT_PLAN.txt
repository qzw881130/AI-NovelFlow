# 宫格图生视频模式开发计划

状态：第八阶段真实章回验收已提交审核；开工前单镜 Phase B 基线已固定在同目录的 GRID_VIDEO_MODE_BASELINE_AUDIT.txt，各阶段记录见 GRID_VIDEO_MODE_STAGE1_REVIEW.txt 至 GRID_VIDEO_MODE_STAGE8_REVIEW.txt。目标是在小说级并存两种模式：新建小说默认「宫格图生视频」；现有小说维持「单镜图生视频」。后者继续使用当前单镜图＋正式 Phase B 生成链路，现有图像、视频、模板选择和历史结果不得因新模式改变。

## 范围与约束

- 模式由小说保存。新小说默认宫格；迁移时现有小说明确标为单镜。已有生成 Shot 的小说不在原小说内切换模式；需要比较时新建小说。
- 宫格 Shot 是叙事单元，包含按顺序排列的 4/6 格；2×2、2×3 在符合剧情 Beat 数时随机选择。3×3 先作为实验选项，经过实测再进入常规随机池。版式、种子和每格 16:9 规格在规划时保存，普通重试不重抽，不填空白格。整板尺寸按每格目标尺寸推算，不固定沿用 1280×720 整板。
- 宫格用于规划和生图。视频阶段默认审阅、裁切成子格，再按台词和动作分配到通常 1–2 格、约 5–10 秒的 Clip；20 秒是上限。整板直传 H3 保留为显式可选策略，不作为唯一解释。
- 两种模式都可输出 Shot 视频和章回合片；新模式沿用已配置的 H3/ComfyUI 工作流，`ref_image_size=match`。不新增任务队列服务、并发调度体系、多用户权限、安全平台或通用工作流引擎。
- 「单镜图模式」与早期「Legacy #13→#14 H3 提示词链路」是两回事。保留前者及其 Phase B；清理后者和 #14A 时先迁出仍被 Phase B 调用的工具函数。历史任务结果及日志可读，但淘汰链路不能被静默重放到 Phase B。

## 开工前：固定旧流程基线

1. 记录现有工作区未提交改动的归属，特别核查本轮实验触及的 ComfyUI、参考图、提示词及前端文件；不批量回退其他改动。
2. 选一条已有单镜小说的无台词和带台词 Shot，保存当前模板选择、实际参考图清单、Phase B 提示词、任务及成片作为回归基线。
3. 列出旧 #13/#14/#14A 的文件、注册项、小说绑定、前后端入口、历史任务引用与 Phase B 间接依赖；将待删项与要迁出的共用函数分开。

## 第一阶段：提示词基础

1. 在提示词管理中标明「共用 / 单镜图 / 宫格图」适用范围。故事上下文、风格、角色/场景/道具模板共用；旧分镜、单镜生图、旧视频导演及正式 Phase B 模板内容与 ID 保持原样。
2. 为宫格模式增加少量独立类型：宫格 Shot/逐格镜头规划、宫格生图提示词、子格到 Clip 规划、宫格 H3 Phase B 提示词。宫格评审如需 LLM 才新增专用模板；裁切、版式抽取和参考图打包由确定性代码完成，不另造提示词。
3. H3 新模板按核对过的官方六段式输出。角色名与 Subject 的映射仅在规范允许的定义部分声明；编译后校验六段结构、其他部分的 Subject 引用、原文台词、说话人与时间归属、参考图编号；校验失败在调用 H3 前停下。模板文本和最终提交文本都留任务快照。
4. 将早期 Legacy #13→#14、#14A 从新任务模板候选与界面移除；确认 Phase B 依赖已迁出后删除旧执行代码和文件。启动时的系统模板初始化不得将已删除的旧模板重新登记。既有用户自定义旧模板先盘点绑定、导出，再处理活跃入口；历史日志保留。

验收：提示词管理能明确区分适用模式；宫格小说只能选共用或宫格模板；单镜小说仍解析原模板；旧 Legacy 链路不再可启动。

## 第二阶段：LLM 日志筛选列表

前后端任务类型列表增加宫格规划、生图提示词、Clip 规划、H3 生成等标签；从**新任务**筛选选项移除淘汰的 Legacy 类型。历史记录继续可按小说/任务查看和导出。先复用现有筛选和列表，不增加额外的日志系统。

验收：每个新 LLM 调用有正确类型、小说、章回、Shot；筛选项与实际任务一致；旧日志仍可读。

## 第三阶段：静态前端页面

先用固定样例数据做宫格模式页面，不接生成 API：直接在原有小说创建/编辑弹窗加入模式选择的静态状态；章回页的叙事 Shot 列表；宫格版式、整板与逐格查看；子格评审与重试入口；子格到 Clip 的对应关系；每条 Clip 的参考图、台词和六段式提示词预览；Shot/章回结果。沿用现有顶部流程与播放器位置。

单镜模式继续展示当前分镜图、视觉状态和 Phase B 页面，不把宫格组件塞进旧页面。拆出模式专用内容区，公用外壳和播放器即可。

验收：两种模式的静态页面可单独走通，旧小说页面没有宫格控件；宫格 Shot 不被误显示成多个单镜 Shot。

## 第四阶段：小说创建与编辑

在原有创建／编辑小说弹窗上完成真实模式交互：创建小说默认选宫格图模式，允许改选单镜图模式；编辑页展示已保存模式。尚未生成 Shot 时可以修改；有生成 Shot 后锁定模式并说明需新建小说比较。模板选择仅列当前模式可用类型。小说卡片/详情显示模式标识。第三阶段禁用的宫格创建提交待存储和 API 接通后启用，不另做一套表单。

验收：新建默认宫格；已有小说显示单镜；复制/编辑模板选择不会跨模式混用。

## 第五阶段：存储结构

1. 给 Novel 增加明确模式字段并迁移已有行到单镜。不要让数据库默认值把既有小说误标成宫格。
2. 给宫格 Shot 增加一个有版本号的宫格数据结构，保存版式、种子、逐格脚本、整板图、子格图、评审状态与修订号。旧 `Shot.image_url` 继续表示单镜主图，不赋予其宫格板的双重语义；Shot 最终视频仍复用现有字段。
3. 图像文件按小说/章回/Shot 分目录保存整板与子格；任务沿用现有 Task，并在任务快照中记录小说模式、宫格修订号、面板顺序、实际 H3 参考图和最终提示词。Clip 规划继续保存在 Shot 计划中，增加宫格专用版本标识，避免按旧计划解析。

验收：旧记录无需重建；普通重试能复现相同版式和图像引用；旧、新任务都能追溯输入。

## 第六阶段：API 与生成服务

按小说模式在入口路由：单镜请求走原服务；宫格请求走新服务。依次接通宫格 Shot 规划、版式随机并落库、整板生图、裁切及逐格检查、Clip 分配、H3 六段式编译与校验、Clip 生成、Shot/章回合片。新模式复用既有素材库、ComfyUI 工作流和合片能力；只在确实需要不同语义处增加 API。外部调用前展示实际参考图与提示词，生成后可逐 Clip 重做。

验收：同一旧小说的 API 路由和结果与基线一致；新小说可从文本走到可审阅的宫格、Clip 和合片；不会把白底多视角角色图或整板意外当成普通子格传入 H3。

## 第七阶段：现有任务队列接入

复用当前任务表、状态、取消与重试机制。宫格规划、整板图、Clip 生成按依赖顺序排队；同一 Shot 的后一步只在前一步确认后运行。ComfyUI 任务保持现有小规模执行方式，先不做大并发、分布式队列或复杂资源调度。批量生成只是依次提交并显示每个 Shot/Clip 的进度和失败位置。

验收：失败可以从受影响的宫格或 Clip 续做，不误改已通过结果；旧队列任务保持原执行路径。

## 第八阶段：测试与验收

每阶段做必要的局部检查，最后集中进行回归和真实生成：

- 单镜模式：对照开工基线，覆盖小说模板选择、分镜图、带/不带台词的 Phase B Clip、参考图清单、合片和历史任务读取。
- 宫格模式：验证版式选择与固定重试、无空格、每格 16:9、裁切顺序、逐格角色/机位数据、Clip 参考图与提示词、六段式及 Subject/台词校验、失败重试。
- 真实端到端：先做 2×2 的无台词与交替台词，再做 2×3；3×3 经单独实验确认后才加入默认随机池。人工检查镜头顺序、过肩轴线、人物连续性、台词及烧入字幕。模型画面质量通过人工审片判断，不把 ASR 的无语音幻觉当作失败证据。
- 清理检查：提示词页面和 H3 路径菜单不再显示 Legacy #13→#14；旧模板不在重启时复活；Phase B 所需共用函数可独立工作。

完成条件：旧单镜图＋Phase B 流程经回归确认；新宫格流程可从创建小说完整走到章回视频；每次视频生成的模式、版式、参考图、提示词与来源 Clip 都能在任务详情追溯。
