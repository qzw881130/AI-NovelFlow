# 示例小说 V1 验收记录

## 旧功能审计

- 旧 `/test-cases` 页面由 `frontend/my-app/src/pages/TestCases`、`src/api/testCases.ts` 和旧多语言文案组成，只提供旧测试 UI。已移除这些不再引用的前端文件；新路由 `/examples` 取代该页面，旧地址在前端重定向。
- 旧 `/api/test-cases` 包含测试用例列表、详情、增删改和 `/{id}/run`。新页面不调用这些接口；旧执行接口保留兼容，但不再从导航或页面暴露。旧执行目前只启动角色解析任务，并非完整流程引擎。
- 三个预设正文来自 `backend/app/constants/test_case.py`。旧 `init_preset_test_cases` 曾在应用启动和测试 fixture 中使用；现在只停止应用启动时自动创建预设小说、章回及角色。初始化函数、`TestCase` 模型和仓库仍保留供现有自动化测试使用，不删除用户数据库里已有的预设记录。
- 正式小说创建入口是 `POST /api/novels/`；章回创建入口是 `POST /api/novels/{id}/chapters`。两者原本分别提交，因此新导入接口抽出正式小说创建的同一实现，并把小说与全部章回放在一次提交中。
- 正式创建默认设置：角色生成和风格提示词使用系统默认模板，其余模板沿用空值默认；宽高比 `16:9`，小说和章回状态 `pending`；世界上下文未锁定。Video Director 配置保持正式创建时的默认值，导入不触发生成。

## 导入流程

`GET /api/examples/` 提供卡片信息；`GET /api/examples/{id}/` 返回全部正文供预览；`POST /api/examples/{id}/import/` 调用与正式创建相同的小说初始化函数，写入章回并提交一次事务。失败会回滚并返回明确错误，成功返回 `novel_id` 后进入小说详情。重复导入每次产生新 ID。业务事件在提交后独立记录；事件或通知失败不影响已提交小说。
